02 · problem§3.2 · PDF стр. 3–4

На training появляется матрица \(|V|\times N\)

paper setup

Teacher forcing

Backbone эффективно вычисляет \(E_1,\dots,E_N\) параллельно, а classifier выдаёт scores для каждого training token по всему vocabulary.

\[E=[E_1\dots E_N],\qquad A=C^{\top}E\in\mathbb{R}^{|V|\times N}\]
Paper §3.2: inference требует distribution для одного token at a time; training оптимизирует все next-token predictions совместно. §3.2, стр. 4: для Gemma 2 2B log-probabilities достигают 89% training memory в их setup.
03 · key reformulation§4 · Eq. (4)

Loss раскладывается на два вычисления

\[\ell=\left(C^{\top}E\right)_{x}-\log\sum_j\exp\!\left(C_j^{\top}E\right)\]
1. score только ground-truth labels    2. log-sum-exp по всему vocabulary
term A

Indexed matrix multiplication

Нужны только \(N\) correct-token scores.

term B

Linear log-sum-exp

Нормализатор учитывает весь vocabulary, но не обязан сохранять все logits.

Наша сноска: это обычный log-softmax правильного класса: \(\log p_y=z_y-\log\sum_j e^{z_j}\). Paper максимизирует log-likelihood; стандартный CE меняет знак.
04 · CCE part A§4.1 · Fig. 2a

Indexed matmul: вычислить только correct-token logits

Полный classifier output

01Для каждого \(E_i\) вычислить scores для всех \(|V|\) columns \(C_j\).
02Потом выбрать score \(C_{x_i}^{\top}E_i\).

Paper §4.1

01Прочитать target id \(x_i\).
02Загрузить только column \(C_{x_i}\) и embedding \(E_i\).
03Сразу выполнить dot product.
Forward indexed matmul использует on-chip SRAM и не аллоцирует отдельную \(|V|\times N\) матрицу.
Paper §4.1: операции выполняются blockwise для эффективности cache; Algorithm 1 / Figure 2a описывают access pattern.
05 · CCE part B§4.2 · Fig. 2b

Linear-log-sum-exp: block matmul → block LSE → update

Regular path

01GEMM строит \(A=C^{\top}E\).
02Blocks результата пишутся в global memory.
03Отдельная reduction читает \(A\) и считает LSE.

CCE forward

01Block matmul \(C_m^{\top}E_n\) в SRAM.
02Сразу LSE вдоль vocabulary-range блока.
03Partial LSE обновляет общий \(LSE_n\).
04Полный \(A\) не материализуется.
Paper §4.2: CCE использует ту же blocking/parallelization strategy, что и efficient matmul. Наша сноска: stable online LSE хранит running scale/max и сумму, поэтому промежуточные logits можно отбросить после reduction.

Backward: формула и приближение

algebra

Восстановить probabilities

Оси PyTorch на этом слайде: E — N×D, C — V×D. Y — one-hot targets, P — N×V.

Для каждого блока повторно вычисляются logits. Сохранённый LSE используется для нормализации.

\[P_{ij}=\exp(Z_{ij}-s_i)\]
\[G=(P-Y)/N,\quad \nabla_E=GC,\quad\nabla_C=G^\top E\]
implementation

Filtering — отдельная настройка

В выбранном commit BF16 auto threshold = 2⁻¹². Проверка блока находится в cce_backward.py. Это не минимальное представимое число BF16 и не доказательство нулевой ошибки.

Сравниваем default, no-filter и exact; публикуем ошибки loss и обоих gradients.

Формулы: REPORT.md §5, при N валидных токенах. Код: upstream 3de376c, cce_backward.py и utils.py. Измерения: results/main/correctness.json.
07 · CE vs CCEsummary

Один objective — разный dataflow

Standard linear + CE

01Вычислить \(A=C^{\top}E\).
02Материализовать \(|V|\times N\) output.
03Получить target log-probabilities / CE.

Cut Cross-Entropy

01Correct-token term: indexed matmul.
02Normalizer: blockwise linear-LSE.
03Backward: recompute + gradient filtering.
Ключевой claim paper: нет необходимости материализовать полную logit matrix в GPU global memory.
Важно для защиты: CCE не уменьшает vocabulary и не меняет training objective. Он меняет реализацию classifier-head cross-entropy.

Appendix A1our explanation

Численный пример: почему не нужен полный softmax output

\[L=-z_y+\log\sum_j e^{z_j}\]
Пример: scores [2, 1, 0], target=0. LSE ≈ 2.407606; loss ≈ 0.407606; p(target) ≈ 0.665241. Для loss достаточно target score и normalizer.
Не из paper: pedagogical example / derivation для вопросов после доклада.
Appendix A2our derivation

Stable / online log-sum-exp

\[\mathrm{LSE}(z)=m+\log\sum_j e^{z_j-m},\qquad m=\max_j z_j\]
Partial reductions можно объединять без сохранения полного вектора logits.
Paper использует online/blockwise LSE; эта алгебраическая расшифровка — наша поясняющая выкладка.
